# Golden test vectors

This directory holds the golden vectors that lock the
`merkle-blake3-64k-v1` Merkle manifest spec.

## Files

- `merkle-vectors.json` &mdash; canonical test vectors covering the four
  documented byte patterns (`linear`, `zeros`, `ones`, `squared`) at
  ten sizes ranging from 1 byte to over a megabyte. Each vector lists
  the deterministic input pattern, expected leaf count, first leaf,
  last leaf, and root hash.

## Where the vectors come from

The vectors are generated by the JavaScript script at
`web/scripts/merkle-vectors.mjs` in the
[BitSeal web monorepo](https://github.com/OrygnsCode/BitSeal).
That script is the canonical source of truth: it produces deterministic
byte streams from each pattern, hashes them with the same BLAKE3 + 64
KiB Merkle construction the web service uses, and emits the JSON file.

The copy in this directory is refreshed each time the spec changes.
The SDK does not regenerate vectors locally; the web monorepo's
generator is the only thing allowed to mint new vectors. If a future
spec change requires new vectors:

1. Regenerate in the web monorepo: `node web/scripts/merkle-vectors.mjs --generate`.
2. Copy the resulting `web/scripts/merkle-vectors.json` into this
   directory, replacing the existing file.
3. Run `python -m pytest tests/test_cross_verify.py` from the SDK
   repo root to confirm the Python implementation still matches.

## How the vectors are exercised

Two paths consume this file:

1. `scripts/merkle_cross_verify.py` &mdash; standalone command-line
   script. Run with `python scripts/merkle_cross_verify.py` to see a
   `[PASS] / [FAIL]` line per vector and an overall exit code. The
   script defaults to the bundled `tests/vectors/merkle-vectors.json`
   when present, falling back to the sibling-repo copy in the
   maintainer's local dev workflow.
2. `tests/test_cross_verify.py` &mdash; pytest test that invokes the
   script via subprocess and asserts every vector passes. Runs on
   every CI build via `.github/workflows/ci.yml`.

If both paths agree, the SDK's Python `MerkleTree` is provably
byte-for-byte equivalent to the JS implementation that produces real
seals at https://bitseal.orygn.tech.

## Why bundle the vectors here

Audit finding M1 noted that the cross-implementation Merkle test
"cannot be run by an outside auditor" because the vectors lived in a
private monorepo. Bundling the vectors in this directory closes that
gap: anyone with a clone of `OrygnsCode/BitSeal-SDK` can run
`pytest tests/test_cross_verify.py` and verify the equivalence claim
end-to-end.

Audit finding M5 noted that the server-side refold logic had no
published regression vectors. The same bundle, exercised by
`tests/test_cross_verify.py` on every CI run, becomes the published
regression guard.
